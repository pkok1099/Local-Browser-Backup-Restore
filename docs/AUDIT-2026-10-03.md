## HIGH

| ID | Finding | Status |
|---|---|---|
| T1-H1 | `verifyScanTab`: verdict `'failed'` without a marker check — crash recovery (`origin=''`) could **close a user tab** whose ID was reused across sessions while displaying an error page | ✅ fixed |

**T1-H1 detail.** Scenario: crawl running → `{tabIds:[…]}` record persisted incrementally →
browser crash → new session resets tab IDs → user tab with the same ID displays
`chrome-error://` → dashboard opened → `cleanupPreviousSessionTabs` → `'failed'` →
user tab closed. Root cause: the `'failed'` branch assumed "recorded ID ⇒ definitely our tab,"
but the tab-ID namespace resets per session. The TDD fix (v8/v9 in
`tests/verify-scan-failed.mjs`): `'failed'` requires a **known** origin; with
`origin=''`, error page → `'foreign'` (never closed). Only a positive marker match
may close a tab on the `''` path. `npm run check` clean, 58 PASS.

## LOW (29, brief)

**Tab/scan:** The 3× retry of `verifyOwnedScanTabsClosed` is dead code (IDs are always
removed in `finally`) · taken-over user tabs are also ungrouped · Stop does not
preempt a hanging debugger read · checkpoints are not validated per origin ·
stale-group race (temporary counter skew) · `waitTabReady` ignores violation-halt ·
reuse-tab failure to settle goes directly terminal · `history.deleteUrl` with a garbage URL
on the `''` path · `'gone'` counted as `cleaned` · failed `remove` still reports `'closed'` ·
marker matches a substring rather than the exact path (risk consciously accepted) · typo `}}` in
tab-ownership & restore logs (7 locations).

**Cloud/backup:** TOCTOU risk when repository visibility changes from private→public during a backup
(narrow window) · malformed manifest replaced without a forensic trace · stale pending items
not cleaned up the same day · UI phase stuck at "encrypting" · raw non-TypedError
for malformed envelope · digest does not include `createdAt`/`generator`
(design decision) · `repoPublic` fails open when `private` is undefined (contrived).

**Restore/dashboard:** placeholder verification based on `windowId` (acceptable) · `replace`
mode is not passed through to `restorePartitions` · token persists in form state after
Connect/Backup · site-data retry cannot be stopped from the UI ·
`withDashboardActivity` fails open without Web Locks (practically unreachable) ·
BroadcastChannel without authentication (non-issue).

**Other libraries:** adaptive CPU monitor silently dies when `onAdjust` throws · site-log
buffer grows without limit while a DB upgrade is blocked · capability probes can leave debris
if cleanup fails · loose settings validation (`""`, `..`) · scheduler state can be manipulated
to suppress schedules + double-run race across contexts · `bytesToB64` for the entire ciphertext
(memory cost, not a bug) · `collectHistory` has no upper bound · `canonicalize` is fragile for
BigInt/circular values (not reachable today).

## Verified TRUE (key strengths)

- **Token hygiene:** only in the `Authorization` header; `#redact` in all dynamic errors;
  `redactConfig` for display; settings import discards the file token.
- **Encryption:** random salt & IV per encryption; AAD binds all parameters; decrypt
authenticates before data is used; `assertUploadSafe` cannot be bypassed;
public+plaintext is always rejected (double-enforced).
- **Upload verification:** re-download + compare sha256 & git blob sha; only HTTP 2xx
counts as success.
- **Tab safety (within a session):** no TOCTOU verify→remove; exactly-once per tab;
guard rejects arrays; single-use permit; unknown verdict → fail-closed;
`restoreSiteData` never closes a reused tab; Stop cleans up all tabs.
- **Restore:** the only deletion path is bookmarks-replace with
`ERR_CONFIRMATION_REQUIRED`; user windows/tabs are never closed; extension storage
allowlist of 5 `bbr.*` keys (token is not backed up).
- **Dashboard:** mutual exclusion across tabs works; password does not leak into state/log;
`window.__api` is not exposed to the web (without content_scripts/WAR/externally_connectable);
corrupt storage clamp is solid; clear fails closed.
- **Sweep:** background without backup-without-schedule; components without
`dangerouslySetInnerHTML`/URL injection; all 15 permissions are used;
no vacuous tests; docs do not contradict the code.

## Audit limitations

- Static code audit and reasoning; Chrome runtime behavior (ID reuse, error-page URL,
  `chrome.tabs.create` with a dead windowId) relies partly on platform knowledge and one
  sandbox probe.
- These platform claims could not be verified from code: `chrome.storage.session` being RAM-only,
  `navigator.locks` on Android/Cromite, and actual GitHub API behavior (simulator only).
- No fuzzing, network penetration testing, or formal cryptographic review (parameters
  assessed from code, not proof).
